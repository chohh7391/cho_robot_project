#### 패키지 재구성

`realsense_apriltag`가 D435와 검출기를 같이 들고 있었는데, OAK를 붙이는 순간 이름이 거짓이
된다 — OAK 스트림에 검출기를 돌리려면 `realsense_apriltag ... launch_camera:=false`를 써야 했다.
의존성으로 선언한 패키지가 하나도 없어서(문서 11줄 + task config 주석 1줄 + CI 2줄이 전부) 분리가
쌌다.

분리하면서 실제로 바뀐 것:

- 검출기가 `image_topic`을 **기본값 없이** 받는다. 틀린 기본값은 "태그가 안 잡힌다"와 증상이
  똑같아서 추측하게 두면 안 된다. `camera_info_topic`은 비우면 이미지 토픽의 형제로 유도한다.
- `rectify:=true`가 카메라 종류와 무관한 인자가 됐다. 전에는 `stream:=color`일 때만 `image_proc`이
  들어갔다. 첫 사용처가 바로 나왔다 — OAK 모노는 드라이버가 rectify를 안 해준다.
- `tag.frames`를 launch가 `geometry.tag_frame_name()`을 import해서 만든다. 노드가 조회에 쓰는 바로
  그 함수라, 두 패키지가 같은 규약을 각자 들고 있던 상태가 없어졌다.

이름 논의: `cho_pose_estimation`은 **이름이 내용보다 넓어서** 반대했다 — 로봇 포즈·카메라 외부
파라미터·VLA 관측이 다 "pose estimation"인데 이 패키지는 그중 하나만 한다. 넓은 이름은 무관한
코드를 불러들이고, TODO §7이 "VLA와 AprilTag를 합치지 않는다"고 못박은 것과 충돌한다.
`cho_apriltag`(방법)보다 `cho_object_pose`(출력)가 먼저 변하지 않는 쪽이다 — `geometry.py`의 2/3이
이미 방법 무관이다(쿼터니언, median/medoid 집계, spread 게이팅).

`cho_camera`로 묶는 것도 반대했다. 한 패키지면 양쪽 벤더에 의존이 걸리고(`depthai` 67 MB vs
`realsense2_camera` 2 MB), `cho_sensor/` 자체가 이미 그룹 디렉토리라 한 단계 더 두면 패키지 둘에
세 단계가 된다.

#### D435 — IR 프로젝터, 그리고 틀렸던 기록

`d435.yaml`에 "이 개체는 프로젝터가 FW로 영구히 꺼져 있다"고 적혀 있었다. **틀렸다.**

```
드라이버 경고   Projector capacity is overrided and disabled by FW
rs-enumerate-devices -o
  Emitter Enabled : 0 ... 2,   default 1     ← 켜짐
  Laser Power     : 0 ... 360, default 150
```

"disabled"는 프로젝터가 아니라 **제어권**이 막혔다는 뜻이다. librealsense에는 옵션이 있는데
`realsense2_camera`가 파라미터를 선언하지 않아(`depth_module.*` 17개 중 emitter 없음) ROS에서는
끌 수 없다. 두 개체 모두 같다.

증상은 태그의 검은 셀마다 흰 점이 뚫려 비트를 못 읽는 것. 잉크가 IR을 통과시키는 문제가
아니었다(태그는 정상적으로 어둡게 찍혔다). 컬러 스트림은 IR 차단 필터가 있어 깨끗하고
`decision_margin` 89.7로 검출된다. 손목 장착으로 가면 롤링 셔터가 문제가 되므로 그때는 프로젝터
창을 테이프로 막고 infra1을 써야 한다.

**`serial_no`가 정수로 넘어가 노드가 거부한다.** `rs_launch`가 launch 인자를 YAML 파라미터 파일에
써넣는데 시리얼이 전부 숫자라 int로 추론된다. upstream 관례인 밑줄 접두사(`_844212070094`)를
launch가 자동으로 붙이게 했다 — `cameras.yaml` 값을 그대로 복붙하면 된다.

#### OAK-D Pro W

MXID `18443010E18F810E00`, `USB SPEED: SUPER`. **부팅 전 `lsusb`는 링크에 대해 아무것도 말해주지
않는다** — MyriadX가 부트로더(PID 2485)에서 USB 2로 열거되고, SDK가 펌웨어를 올린 뒤 SuperSpeed로
재열거된다. 처음에 480M을 보고 "대역폭 제한"이라고 한 건 오독이었다.

```
i_pipeline_type: RGBSTEREO   기본 RGBD는 모노 쌍 대신 depth를 낸다
i_enable_ir: false           Pro의 도트 프로젝터가 D435와 똑같은 일을 한다
```

공장 캘리브가 `camera_info`에 그대로 나온다(`rational_polynomial` 8계수 — 광각이라 `plumb_bob`으로
표현이 안 된다). 모노는 `image_raw`만 나오고 드라이버가 RGB에만 rectify를 붙인다.
udev 룰(`03e7`)이 없으면 장치를 못 연다.

#### 캘리브레이션에서 확인한 것

- **`--square`는 `K`·`D`에 영향이 없다.** 물체 점을 전부 s배 하면 tvec이 1/s배로 상쇄된다.
  정밀 실측이 필요한 건 AprilTag의 `size` 쪽이다.
- **AprilTag `size`는 검은 사각형(8칸) 한 변이다.** 흰 테두리는 뺀다. 240 px(10칸) 이미지에서 검출
  코너가 544→736 = **192 px = 8칸**으로 나오는 것으로 확인.
- **흰 quiet zone이 없으면 검출이 안 된다.** 인쇄한 태그를 검은 테두리에 맞춰 잘라 어두운 받침에
  붙였더니 전혀 안 잡혔다. 화면으로 띄우면(PNG에 테두리 포함) 잘 된다.
- **막대가 초록이 되면 바로 CALIBRATE.** 223장까지 모았더니 이미지 460 MB + 야코비안
  24084 × 1347이 되어 멈춘 것처럼 보였다. 로그를 계산해보니 **54장에서 이미 네 막대가 전부 1.0**
  이었다. `goodenough = (len(db) >= 40) or all(progress == 1.0)`이고, 40장 규칙은 비상구지 목표가
  아니다. 계산 중 창이 안 그려지는 건 정상이다(solver가 GUI 스레드에서 돈다).
- 프린터가 100%로도 줄인다. 체커보드 설계 25 mm → 실측 24.2 mm(가로 242/10, 세로 170/7이 0.35%
  안에서 일치 → 균일 배율).
